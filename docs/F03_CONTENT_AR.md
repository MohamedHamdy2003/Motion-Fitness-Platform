# F03 — مكتبة المحتوى والوسائط

F03 بتجهز المكتبة اللي الإدارة هتبني منها البرامج والوجبات لاحقًا. التنفيذ الحالي Backend APIs؛ شاشة إدارة مرئية ضمن F18.

## اللي اتبنى

- إدارة التمارين: عنوان، وصف، خطوات الحركة، العضلات، المعدات، مرجع المحتوى وملف الوسائط.
- إدارة الأطعمة: طريقة وحالة التحضير، القيم لكل 100 جرام، مصدر القيم والمكونات وأوزانها. القيمة غير المعروفة محفوظة كـ null.
- إدارة المكونات: الحساسية والوسوم الغذائية وحالة التحقق ورقم مراجعة للبيانات.
- التمرين والطعام يبدأوا مسودة. النشر يثبت النسخة؛ تعديل المنشور ينشئ نسخة جديدة. الأرشفة تحفظ المحتوى القديم.
- الطلبات تحتاج حسابًا بدور ADMIN أو CONTENT_EDITOR موجود في قاعدة البيانات. التسجيل العادي لا يمنح هذه الأدوار.
- مكتبة الوسائط تدعم JPEG وPNG وWebP وMP4 حتى 100 ميجابايت. رفع الملف يتم برابط مؤقت ثم finalize يتحقق من الحجم ونوع المحتوى وتوقيع بدايته، ويحفظ نسخة نهائية منفصلة. ده مش فحص فيروسات أو فك ترميز كامل للفيديو.
- الوسائط النهائية للمكتبة مشتركة بين محرري المحتوى، وروابط قراءتها مؤقتة. تخزين S3 الحقيقي ما زال يحتاج إعداد حساب ومفاتيح.

## تجربة الطلبات

طلبات Bruno الجديدة داخل Admin exercises وAdmin foods وAdmin ingredients وAdmin Media. استخدم توكن حساب له صلاحية، ثم ضع contentId أو ingredientId من نتيجة الإنشاء.

1. POST /admin/ingredients لإنشاء مكون.
2. POST /admin/foods أو /admin/exercises باستخدام slug وcontent.
3. PATCH /admin/{kind}/{id} باستخدام content كامل وexpectedRevision من آخر استجابة.
4. POST /admin/{kind}/{id}/publish باستخدام expectedRevision لنشر آخر مسودة.
5. GET /admin/{kind}/{id} يعرض النسخ، وDELETE يؤرشف الهوية.

القوائم تدعم limit وoffset. تعديل المكونات يستخدم expectedRevision الذي يساوي metadata_version.

## حدود الدفعة الحالية

المكتبة الإنتاجية تبدأ فارغة: لا توجد بيانات غذائية أو تعليمات تمارين معتمدة أضيفت تلقائيًا. أمثلة الاختبارات مصطنعة للاختبار فقط. الاستيراد جاهز من ملف محلي باستخدام CONTENT_DATASET_PATH مع npm run seed:content. الملف يحتوي datasetId وversion ومصفوفات ingredients وexercises وfoods. كل عنصر يحتوي id ثابت وslug وcontent بنفس صيغة API. الاستيراد يبدأ بمسودات ولا ينشر تلقائيًا. تكرار نفس نسخة الملف لا يكرر البيانات؛ تغيير نفس النسخة يرفض، وأي خطأ يتراجع عن الاستيراد كله.

DELETE /admin/media/{id} يؤرشف الملف غير المستخدم ويمنع إصدار روابط جديدة له. الملفات المرتبطة بمحتوى لا يمكن أرشفتها. الحذف الفعلي وسياسة تنظيف الرفعات المهجورة ينتظران اعتماد سياسة الاحتفاظ. الروابط الصادرة قبل الأرشفة تنتهي خلال خمس دقائق.

البرامج والوجبات والأجزاء الغذائية وترشيح برنامج للمستخدم ليست ضمن هذه الدفعة. البيانات المؤكدة للحساسية تحتاج مراجعة بشرية؛ الصلاحية التحريرية وحدها لا تثبت صحة المحتوى.

مراجعة الإكمال: قائمة GET /admin/media تعرض الملفات المشتركة والرفعات الخاصة بالمحرر. اعتماد الملف ونقل ملكيته للمكتبة يتمان في تحديث واحد. الأطعمة تظهر في قائمة المستخدم بعد النشر فقط وتختفي عند الأرشفة. عضوية المكونات في وصفة منشورة محمية من التعديل. يمكن ضبط S3_FORCE_PATH_STYLE=true حسب endpoint التخزين.

لمنح صلاحية محرر لحساب مسجل في قاعدة تطوير محلية: npm run dev:grant-editor -- EMAIL. الأمر يرفض قواعد البيانات البعيدة وبيئة الإنتاج.
