# حالة الحسابات وربط الخدمات

**آخر تحديث: 4 نوفمبر 2026**

ده ملخص للإعداد الحالي والخطوات المتبقية. لا تضع كلمات مرور أو مفاتيح أو ID tokens في Git أو المحادثة.

## جاهز حاليًا

| الخدمة         | الإعداد والحالة                                                                                                                                       |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| GitHub         | المستودع `MohamedHamdy2003/Motion-Fitness-Platform` هو مصدر الكود. تغييرات `dev` تمر على CI؛ النشر من `main` فقط وبعد طلب إصدار صريح.                 |
| AWS EC2        | Amazon Linux 2023 x86_64، والعنوان العام `13.49.114.20`. Docker وSSM جاهزان؛ SSH مقصور على عنوان IP جهاز الإدارة.                                     |
| AWS RDS        | PostgreSQL على RDS؛ الاتصال من EC2 يستخدم TLS وشهادة RDS.                                                                                             |
| AWS S3         | Bucket خاص متصل عبر IAM Role على EC2؛ لا تضع مفاتيح S3 ثابتة في إعدادات التطبيق. اختبر رفع ملف فعليًا من API قبل الاعتماد عليه.                       |
| HTTPS          | Caddy يخدم الـAPI عبر IP بدون شراء Domain. عنوان API هو `https://13.49.114.20/api/v1`. لا تحتاج DNS لهذا العنوان.                                     |
| GitHub Actions | ينشر commit من `main` إلى EC2 عبر SSM بعد نجاح CI. راجع حالة كل Action وSHA المنشور على السيرفر.                                                      |
| Gmail SMTP     | تم إعداد SMTP وقبول رسالة OTP حقيقية في اختبار سابق. الإعداد السري في `.env.aws` على EC2 فقط.                                                         |
| Google OAuth   | Android وWeb Client IDs مضافة لإعداد الـBackend، وإصدار challenge يعمل. تسجيل الدخول الحقيقي يحتاج تنفيذ التطبيق وإرسال ID token وchallengeId وnonce. |

## مؤجل أو غير مجهز

- **Apple Sign-In:** مؤجل حسب قرار المستخدم إلى أن يتوفر Apple Developer وإعداد تطبيق iOS.
- **Staging منفصل:** غير موجود حاليًا؛ قيمة Staging في Bruno placeholder وتنتهي بـ`.invalid`.
- **الذكاء الاصطناعي:** لا يوجد مزود إنتاج معتمد. يلزم اختيار الموديل ومراجعة الاحتفاظ بالبيانات قبل التفعيل.
- **DNS وDomain:** غير مطلوبين للإنتاج الحالي الذي يستخدم IP وشهادة HTTPS.
- **حذف الحساب:** تنظيف البيانات والملفات النهائي ينتظر اعتماد سياسة الاحتفاظ والحذف.

## خطوات المتابعة

1. push إلى `dev` يشغّل CI فقط. لا تدمج إلى `main` ولا تشغل نشرًا إلى EC2 حتى يطلب المستخدم إصدارًا صريحًا. وقتها راجع GitHub Actions وSHA المنشور.
2. اختبر Google Sign-In من تطبيق Android: اطلب challenge، مرر nonce إلى Google بالطريقة المتوافقة مع الـSDK، ثم أرسل `idToken` و`challengeId` إلى الـBackend.
3. اختبر مسار S3 من Bruno باستخدام حساب مخوّل: upload intent، رفع الملف إلى الرابط المؤقت، finalize، ثم قراءة الملف.
4. مكتبة الأغذية والوجبات F08 قيد التنفيذ على فرع تطوير، وبذورها من USDA FoodData Central كمسودات. تفاصيلها في [شرح F08](F08_FOOD_MEAL_LIBRARY_AR.md).
