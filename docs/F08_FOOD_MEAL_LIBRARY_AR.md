# مكتبة الأغذية والوجبات — F08

آخر تحديث: 4 نوفمبر 2026.

## ما الذي يضيفه هذا الجزء؟

يبني أساس مكتبة قابلة لإعادة الاستخدام للأطعمة والأقسام والوجبات. المسؤول ينشئ الطعام كمسودة، ويراجع بياناته ومصدره، ثم ينشره. بعد ذلك يمكن تجميع نسخ الأطعمة المنشورة في قسم بدائل بحصص محددة، ثم تركيب وجبة من عناصر هذه الأقسام. النسخ المنشورة ثابتة؛ تعديل المحتوى المنشور لاحقًا يتطلب نسخة جديدة.

هذه الدفعة تنفذ كتالوج الإدارة فقط. إنشاء برامج التغذية، إسناد الوجبات للمستخدم، الفلاتر الشخصية، التبديل وتتبع الاستهلاك مراحل لاحقة من F08/F04/F06.

## قواعد البيانات والبذور

- Migration `1793448003000-NutritionLibrary` تنشئ أقسام بدائل الطعام، أعضائها، أقسام الوجبات، نسخ الوجبات وعناصرها.
- `npm run seed:content` يستورد ملف `src/infrastructure/database/seeds/data/nutrition-library.v1.json` بشكل معاملاتي وقابل لإعادة التشغيل.
- كل الطعام والوجبات المستوردة يبدأ بحالة `DRAFT`؛ لا ينشر Seeder أي سجل تلقائيًا.
- بيانات العناصر الغذائية لكل 100 غرام مأخوذة من USDA FoodData Central، مجموعة SR Legacy النهائية المنشورة في أبريل 2018. USDA تعتبر بيانات FDC ملكية عامة تحت CC0 1.0 وتطلب الإشارة إلى المصدر. هذه المجموعة تاريخية وغير محدثة؛ يجب مراجعة التحضير والحصص والمعلومات الغذائية قبل نشر كل سجل.
- الوجبات الست أمثلة تحريرية محلية مجمعة من عناصر USDA، وليست وصفات أو توصيات صادرة عن USDA. الحصص الأولية تقريبية ولا تضمن تساوي السعرات أو المغذيات بين البدائل.
- حالات مكونات الطعام والحساسية مزروعة `UNKNOWN`؛ لا تعتبر غياب الحساسية المعلنة إثباتًا للسلامة. مسؤول المحتوى يراجع المكونات والملصقات محليًا قبل النشر.

## واجهات إدارة المكتبة

كل المسارات تتطلب حسابًا مؤكدًا ودور `ADMIN` أو `CONTENT_EDITOR`. استخدم فولدر `Admin Food Library` داخل Bruno.

| Method | Endpoint                           | ماذا يفعل                       | متطلبات/ملاحظات                                                     |
| ------ | ---------------------------------- | ------------------------------- | ------------------------------------------------------------------- |
| GET    | `/admin/food-sections`             | يعرض أقسام بدائل الطعام         | يدعم `limit` و`offset`                                              |
| POST   | `/admin/food-sections`             | ينشئ قسمًا كمسودة مع أعضاء وحصص | كل عضو يشير إلى `foodVersionId`                                     |
| PATCH  | `/admin/food-sections/:id`         | يعدل المسودة أو ينشئ نسخة جديدة | يتطلب `expectedRevision`                                            |
| GET    | `/admin/food-sections/:id`         | يعرض القسم ونسخه وأعضائها       | يعرض حالة نسخة الطعام المرتبطة                                      |
| POST   | `/admin/food-sections/:id/publish` | ينشر أحدث نسخة                  | يتطلب بديلين على الأقل وأطعمة منشورة، مع `expectedRevision`         |
| DELETE | `/admin/food-sections/:id`         | يؤرشف القسم                     | يتطلب `expectedRevision`                                            |
| GET    | `/admin/meal-sections`             | يعرض أقسام الوجبات              | القسم مثل إفطار أو وجبات رئيسية؛ ليس ضمانًا لتكافؤ التغذية          |
| POST   | `/admin/meal-sections`             | ينشئ قسم وجبات                  | `slug` فريد و`title`                                                |
| GET    | `/admin/meal-sections/:id`         | يعرض قسم الوجبات                | —                                                                   |
| PATCH  | `/admin/meal-sections/:id`         | يعدل اسم وعنوان القسم           | —                                                                   |
| DELETE | `/admin/meal-sections/:id`         | يؤرشف القسم                     | —                                                                   |
| GET    | `/admin/meals`                     | يعرض أحدث نسخة من كل وجبة       | يدعم `limit` و`offset`                                              |
| POST   | `/admin/meals`                     | ينشئ وجبة مسودة وعناصرها        | العناصر تشير لأعضاء أقسام الطعام المنشورة قبل نشر الوجبة            |
| PATCH  | `/admin/meals/:id`                 | يعدل المسودة أو ينشئ نسخة جديدة | يتطلب `expectedRevision`                                            |
| GET    | `/admin/meals/:id`                 | يعرض الوجبة ونسخها وعناصرها     | يتضمن الحصة وحالة الطعام والقسم                                     |
| POST   | `/admin/meals/:id/publish`         | ينشر أحدث نسخة من الوجبة        | يتطلب عناصر وقسمًا وأقسام طعام وأطعمة منشورة، مع `expectedRevision` |
| DELETE | `/admin/meals/:id`                 | يؤرشف الوجبة                    | يتطلب `expectedRevision`                                            |

في عناصر الوجبة `exchangeUnits` عدد وحدات العضو المختار. وعند عرض كميات التغذية مستقبلًا، الكمية بالجرام تحسب من `portionGPerUnit × exchangeUnits`، ثم المغذيات من القيم لكل 100 غرام. الخادم لا يخترع حصصًا ولا يقرر أن بديلين متساويان غذائيًا.

## مصادر USDA

- [FoodData Central: تنزيلات البيانات](https://fdc.nal.usda.gov/download-datasets/) — يحدد إصدار SR Legacy أبريل 2018.
- [USDA FoodData Central API Guide والترخيص](https://fdc.nal.usda.gov/api-guide/) — يوضح الاستخدام والترخيص CC0 والاستشهاد المطلوب.
- يحتوي كل سجل في ملف Seeder على رابط صفحة المغذيات الخاصة به باستخدام FDC ID، مع الصيغة والتحضير المطابقين للسجل.

## تجربة التطوير

بعد تشغيل PostgreSQL وتهيئة `.env`:

```bash
npm run migration:run
npm run seed:lookups
npm run seed:content
npm run dev:grant-editor
npm run dev
```

ملف Seeder يكرر الاستيراد بأمان لنفس رقم الإصدار. لو تغير محتوى نفس الإصدار، يرفض الاستيراد؛ أنشئ رقم إصدار جديدًا بعد مراجعة البيانات.
