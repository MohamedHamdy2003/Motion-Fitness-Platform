# F05 — اختيار البرنامج بمساعدة AI

الـBackend يفلتر البرامج المنشورة بثلاثة شروط معًا: الهدف الأساسي مطابق، عدد أيام التدريب مطابق، والمستوى ضمن المستويات المدعومة. يرسل المرشحين فقط إلى Mastra لاختيار برنامج واحد أو NO_MATCH. التوصية ليست إسنادًا؛ الإسناد والجدول الشخصي يأتيان في F06.

## التشغيل

1. شغّل migrations المعتادة. الجداول الجديدة matching_rulesets وrecommendation_runs.
2. استخدم نفس AI_MODEL والمزوّد الحاليين في ai-service. ضع رابط الخدمة الخاص `/internal/v1/match` في AI_MATCHING_URL في بيئة الـBackend. نفس AI_SERVICE_TOKEN بطول 32 على الأقل في الخدمتين. يلزم AI_RETENTION_APPROVED=true بعد الموافقة على معالجة البيانات. لا تُرسل أسرار إلى Bruno أو GitHub.
3. اسم model في ruleset يطابق AI_MODEL حرفيًا. الخدمة ترفض الموديل المختلف. لا تغيّر المزوّد أو الموديل تلقائيًا.
4. الأدمن ينشئ ruleset كمسودة، يشغّل محاكاة على حالات راجعها مختص، ثم ينشر بإقرار qualityApproved=true ومرجع تقرير التقييم evaluationReference. الإقرار موافقة بشرية، وليس تقييم جودة تلقائيًا. لا يوجد ruleset منشور تلقائيًا.
5. onboarding يضع طلبًا في الخلفية. تعديل بيانات الاختيار يضع طلبًا جديدًا، والطلب المتكرر لنفس البيانات والقواعد والمرشحين يعيد سجل التشغيل الحالي. لا يحتاج العميل أي مفتاح تكرار أو رقم نسخة.
6. يقرأ الموبايل GET /me/matching/status. POST /me/matching/retry لإعادة الطلب بعد تجهيز الإعدادات أو بعد الفشل. محاكاة الأدمن تُقرأ من سجل التشغيل.

الـworker يعمل مع عملية API، كل 3 ثوانٍ. قاعدة البيانات تحفظ الطلبات أثناء إعادة التشغيل، وlease مدتها 45 ثانية تمنع عدة workers من تنفيذ نفس السجل. محاولتان بحد أقصى لكل run؛ بعدهما يلزم retry صريح. مهلة مزوّد AI محدودة، ولا يبقى transaction مفتوحًا أثناء اتصاله. إعادة محاولة اتصال غامض قد تُحسب تكلفة ثانية لدى المزوّد.

## الحالات والضوابط

- NOT_STARTED: لا يوجد تشغيل سابق. INCOMPLETE_PROFILE: البيانات ناقصة. CONFIGURATION_REQUIRED: لا توجد قواعد منشورة.
- PENDING/PROCESSING: قيد التنفيذ. MATCH: توصية صحيحة، assignmentStatus=NOT_ASSIGNED. NO_MATCH: لا يوجد اختيار مناسب؛ لا يُستدعى AI عند انعدام المرشحين.
- FAILED: خطأ مزوّد أو استجابة غير صالحة؛ failureCode كود آمن. STALE: بيانات المستخدم أو المرشحون أو القواعد تغيرت؛ اطلب التشغيل من جديد.
- لا يوجد كتالوج برامج للموبايل. تفاصيل المرشحين والقياسات في سجل الأدمن فقط.
- لا تُرسل أسماء أو بريد أو هاتف أو تاريخ ميلاد إلى المزوّد. يُحسب العمر محليًا، ويُرسل مع القياسات والهدف والمستوى والجنس وعدد أيام التدريب. لا تُرسل إصابات أو تفضيلات أطعمة في F05.
- BMI معلومة سياقية بدون تصنيفات أو استبعاد تلقائي. لا تُفترض معدات أو أوقات غير مسجلة. لا يستخدم الجنس كشرط أهلية.
- الاستجابة المنظمة لا تقبل إلا IDs من المرشحين وأكواد أسباب محددة. لا توجد ادعاءات طبية أو شرح حر مولّد للمستخدم. يتم فحص حداثة البيانات قبل وبعد اتصال المزوّد.
- حد المرشحين 200 وحجم سياق 512KB؛ تجاوز الحد يرجع فشلًا واضحًا، دون إسقاط مرشحين بصمت.
- نشر قواعد جديدة يؤرشف السابقة ذريًا. التعليمات والموديل والإصدارات المنشورة غير قابلة للتعديل.
- حذف حساب المستخدم يحذف سجلات توصياته بعلاقة ON DELETE CASCADE. استخدم بيانات اصطناعية في المحاكاة؛ لا تضع معلومات تعريف شخصية في التعليمات.

## الاختبار

الاختبارات تستخدم مزوّدًا مقلّدًا لاختبار القيود والأخطاء والخصوصية؛ لا تثبت جودة الاختيار الرياضي. اعتماد الإطلاق الفعلي يحتاج تقييم خبير للنماذج وتعليماتها، وتجربة اتصال حقيقي في بيئة مجهزة. لم يُنفذ اتصال مدفوع في هذه الدفعة.

مرجع API للمكتبة المستخدمة: [Mastra structured output](https://mastra.ai/blog/migration-guide-streaming).

لتقييد استهلاك المزوّد، كل مستخدم يمكنه إنشاء 10 تشغيلات جديدة بمرشحين خلال نافذة 15 دقيقة، بما فيها التشغيل التلقائي بعد تعديل الملف. إعادة استخدام run موجود لا تستهلك تشغيلًا جديدًا. تجاوز الحد يرجع matching.status=RATE_LIMITED بدون التراجع عن تعديل الملف.
