# F04 — إدارة البرامج والجدول الغذائي المقترن

هذه الميزة مدمجة على فرع `dev`. هدفها أن ينشئ محرر المحتوى البرنامج الرياضي وجدوله الغذائي كحزمة واحدة، ويعدّلها وينشرها من دون أن تنفصل أيام التدريب عن أيام التغذية.

## قواعد البناء

- كل دورة شهرية في F04 هي 4 أسابيع بالضبط (28 يومًا)، وليست شهرًا ميلاديًا يتغير بين 28 و31 يومًا. الأسبوع 7 أيام؛ كل أسبوع يحتوي عدد أيام التدريب المحدد للبرنامج (2 إلى 5)، والباقي أيام راحة.
- `trainingDaysPerWeek` في قالب F04 يخزن عدد أيام التدريب فقط، ومخطط البرنامج يعرض خانات اليوم 1 إلى 7 لكل أسبوع. يختار المستخدم أيامه الثابتة في ملفه الشخصي، ويحفظها `training_days_per_week` كقائمة رموز أيام. يظل ربط أيام المستخدم بخانات الأسبوع جزءًا من إسناد البرنامج اللاحق، وليس من منشئ محتوى F04.
- يوم التدريب يحتوي تمرينًا واحدًا أو أكثر، ولكل تمرين وصفة مجموعات وتكرارات أو مدة. يوم الراحة لا يحمل تمرينًا.
- كل يوم يرتبط بيوم تغذية واحد له نفس الترتيب من بداية البرنامج. يحدد المحرر أنواع الوجبات وأوقاتها لكل يوم؛ يسمح بعدد وأنواع مرنة، لكن النشر يتطلب وجبة واحدة على الأقل في كل يوم.
- البرنامج وجدول التغذية نسختان مقترنتان. إنشاء الجدول أو تعديله أو نشره يتم في معاملة قاعدة بيانات واحدة.
- المسودات قد تشير إلى محتوى مسودة أو منشور. النشر يتطلب تمارين منشورة ووجبات منشورة ومتاحة، وأيامًا مكتملة ومقترنة. النشر يثبت النسخة ولا يمكن تعديلها؛ التغيير اللاحق ينشئ نسخة جديدة.
- تلميحات البرنامج تُحفظ كمسودة منفصلة وتحتاج موافقة صريحة قبل نشر برنامج يحتوي عليها. لا يستدعي هذا المسار خدمة AI.

## واجهات المحرر

كل المسارات تحتاج Bearer token لبريد مؤكد ودور `ADMIN` أو `CONTENT_EDITOR`. ابدأ من مجلد Bruno `reference/Admin Programs`.

| الطريقة | المسار                                      | الاستخدام                                                                                                  |
| ------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| GET     | `/admin/programs`                           | قائمة البرامج المنشورة والمسودات مع التصفية والصفحات.                                                      |
| POST    | `/admin/programs`                           | إنشاء برنامج ونسخة تغذية ومسودة جدول كاملة ذريًا. يحتاج `Idempotency-Key`.                                 |
| GET     | `/admin/programs/:id`                       | قراءة أحدث نسخة مع الأسابيع والأيام والتمارين ووجبات كل يوم.                                               |
| PATCH   | `/admin/programs/:id`                       | استبدال محتوى المسودة كاملًا؛ يحتاج `expectedVersion` و`Idempotency-Key`. بعد النشر ينشئ نسخة مسودة جديدة. |
| POST    | `/admin/programs/:id/publish`               | التحقق من البرنامج والتغذية ونشرهما ذريًا؛ يحتاج `expectedVersion` و`Idempotency-Key`.                     |
| DELETE  | `/admin/programs/:id`                       | أرشفة البرنامج مع الاحتفاظ بالنسخ؛ يحتاج `expectedVersion` و`Idempotency-Key`.                             |
| POST    | `/admin/programs/:id/hints`                 | إضافة مسودة تلميح منظمة؛ يحتاج `expectedVersion` و`Idempotency-Key`.                                       |
| POST    | `/admin/programs/:id/hints/:hintId/approve` | اعتماد أحدث مسودة تلميح؛ يحتاج `expectedVersion` و`Idempotency-Key`.                                       |

مفتاح عدم التكرار من 8 إلى 128 حرفًا من الحروف الإنجليزية أو الأرقام أو `_` أو `-`. أعد استخدام المفتاح فقط عند إعادة إرسال نفس الطلب بعد انقطاع؛ المفتاح نفسه مع محتوى مختلف يرجع `IDEMPOTENCY_CONFLICT`.

## مثال هيكل اليوم

```json
{
  "kind": "TRAINING",
  "workout": {
    "title": "Full body A",
    "description": "Workout notes",
    "exercises": [
      {
        "exerciseRevisionId": "<published-exercise-revision-id>",
        "prescription": {
          "mode": "REPS",
          "setCount": 3,
          "repsMin": 8,
          "repsMax": 12,
          "restSeconds": 60
        }
      }
    ]
  },
  "meals": [
    {
      "mealType": "LUNCH",
      "localTime": "12:00",
      "mealVersionId": "<published-meal-version-id>"
    }
  ]
}
```

يوم الراحة يستخدم `{"kind":"REST","meals":[...]}` من دون حقل `workout`. الوصفة الزمنية تستخدم `mode: "DURATION"` مع `durationSeconds` بدل `repsMin` و`repsMax`. كل عنصر تمرين يشير إلى `exerciseRevisionId` ثابت؛ محتوى تلك النسخة يتضمن `mediaId` إذا أضيف فيديو.

## ما لا تغطيه هذه الدفعة

F04 هي أداة بناء ونشر للمشرفين. لا تُعيّن البرامج للمستخدمين ولا تختارها تلقائيًا؛ الترشيح يأتي في F05، والإسناد وجدولة البرنامج للمستخدم في F06. كذلك لا تتضمن F04 واجهة اللاعب لجلب يومه الحالي أو تنفيذ التمرين، تبديل الوجبات أو تسجيل الاستهلاك. الواجهة الحالية `/admin/programs/:id` مخصصة للمشرف؛ استخدام فيديو داخل التطبيق يحتاج واجهة لاعب مقيّدة ترجع رابط S3 مؤقتًا بعد تنفيذ الإسناد. راجع [دليل مكتبة التمارين والفيديو](EXERCISE_LIBRARY_AND_VIDEO_AR.md).
